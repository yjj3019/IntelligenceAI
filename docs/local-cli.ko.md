# 본인의 로컬 CLI 실행

사용자는 본인의 PC에 설치한 CLI와 기존 로그인을 사용한다. 프로젝트 GUI는
설치 상태, 정상 로그인 조회 결과, 사용자가 요청한 실제 실행 결과를 구분한다.
플랜·가격·청구·구독 변경은 각 AI 서비스에서 관리하며 이 경로의 선행 조건이 아니다.
기존 API 검토 기능은 고급 항목에 둔다.

승인 준비는 후보·증거·정책·저장 위치·generation·세션·provider·실행 파일 식별자와
입력 SHA256을 함께 고정한다. 승인은 5분 후 만료된다. 명시적으로 승인한 요청만
PostgreSQL 대기열에 등록하며 별도 로컬 worker가 소비한다. API 서버는 CLI나
repository 코드를 실행하지 않는다. 결과는 프로젝트 인가를 거친 비공개 텍스트 산출물이다.

CLI 실행은 요청당 1회·최대 60초·사용자당 동시 실행 1개로 제한한다. CLI 내부 요청
횟수는 보장하지 않는다. 이중 클릭·응답 유실·파싱 실패·시간 초과로 자동 재호출하지
않는다. 실행 중 취소는 우선 `CANCEL_REQUESTED`이며, 로컬 프로세스 종료와 원격
취소를 별도로 기록한다. 결과가 불명확하면 자동 복구로 lease를 지우지 않는다.

Claude 2.1.296와 Codex 0.162.1에는 문서화된 정상 제한 옵션을 적용한다. 관리 정책은
유지하며 권한 거부를 우회하지 않는다. Grok 1.0.50은 builtin 도구 필터만으로 MCP와
hook을 제외하는 방법이 확인되지 않아 실행을 보류한다. 인증 파일을 읽거나 옮기지
않고 표준 OS 환경만 자식에게 전달한다. Windows Job과 POSIX process group의
종료 확인은 임의 코드를 안전하게 실행하는 OS sandbox 검증을 뜻하지 않는다.

입력은 요청·후보 원문·고정된 검사 증거를 각각 한 번씩 담는 UTF-8 JSON이다. 한글을
불필요한 `\uXXXX` 문자열로 바꾸지 않는다. 동일한 후보 원문은 출처 이름을 모두 남기고
한 번만 전송한다. 이전 답변·전체 로그·GUI 상태·실행 시각은 자동으로 붙이지 않는다.
8,000 bytes를 넘으면 전송 전에 거절하며 조용히 자르지 않는다. 실제 payload 크기와
형식은 승인에 묶으므로 변경된 입력에 이전 승인을 사용할 수 없다. 전역 서명용
canonical은 유지한다. 실제 토큰 절감률은 측정하지 않았다.

이번 실행의 토큰과 계정 구독 한도는 별도 표시한다. CLI가 제공한 필드·출처·측정 시각을
보존하며 누락값은 미확인으로 둔다. Codex cached input은 input에 다시 합산하지 않는다.
Grok의 input은 uncached 값이며 불완전 사용량 표시도 유지한다. 비용을 청구액으로
해석하지 않는다. Codex 공식 로컬 `account/rateLimits/read`는 모델 turn 없이 조회하며
구간 길이·사용률·초기화 시각을 저장한다. 10,080분은 7일 구간이다. Claude·Grok의
독립 headless 한도 조회는 미확인이다. GUI 새로고침은 저장된 상태만 읽는다.

운영 명령과 공식 근거는 [영문 실행 안내](local-cli.md)에 정리했다. 초기 연결은 본인의
PC에서 운영자가 기존 프로젝트·사용자 ID에 worker를 등록하는 방식이다. 공개 서버에서
여러 사용자의 worker를 가입시키는 프로토콜은 아직 구현하지 않았다. 공유 PC 계정을
다른 사용자에게 연결하거나 credential을 서버로 복사해서는 안 된다. 실제 PostgreSQL·OIDC
연결과 공개 배포는 확인된 대상에서 별도로 검증한다. 합성 fixture 테스트를 운영 성공으로
보고하지 않는다.
